# Dailo V1.9 Implementation Plan — Beta-ready

**Goal:** Make Dailo installable, offline-capable, data-safe and Serbian for a small iPhone Safari beta, without a backend.

**Spec:** `docs/superpowers/specs/2026-10-07-todo-v1-9-design.md`

**Ledger:** `docs/superpowers/progress-v1-9.md`

**Baseline:** V1.8 on `main` (`5e4ba82`) plus V1.9 docs. Verification commands: `CLAUDE.md` → "Safe default commands" and "Cloud sessions".

**Tech stack:** HTML, CSS, vanilla JavaScript (classic scripts), Node built-in test runner, existing Python static checks.

## Global execution rules

- Branch: work on the session branch and merge into `main` through a PR.
- For every step:
  1. Write a focused failing test first and confirm it fails.
  2. Implement the smallest compatible change.
  3. Run the focused test, the full Node suite, JavaScript syntax checks and `git diff --check`.
  4. Append evidence to the ledger.
  5. Commit and push.
- Preserve every V1.8 contract except the approved exceptions listed in the spec (Search labels translated, `index.html` text translated).
- Tests that slice `js/app.js` into a `vm` must keep their assertions. When new code in a sliced region needs a new identifier (for example `t`), add an identity stub to that test's context.
- Never weaken an assertion to make a test pass. When a regex matches source text that legitimately changes (e.g. `>More<` → `>Još<`), update it to the new literal with the same intent.
- No new runtime library. Vendored fonts and icons are assets and keep their license files.
- Do not open isolated Chromium or the user's Chrome. iPhone acceptance is manual and is recorded only from the user's report.

  - Docs.
