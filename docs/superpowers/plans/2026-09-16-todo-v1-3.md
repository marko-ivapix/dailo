# To Do App V1.3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade the existing V1.2 static HTML/CSS/vanilla-JS prototype to V1.3 with Calendar & Planning, Areas, Goals, Habits, Templates, Saved Views, custom shortcuts, advanced recurring workflows, universal confirmation+Undo deletion, and safe V3 storage/migration while preserving all V1.2 behavior and data.

**Architecture:** Keep the existing static app and UMD-style globals. Preserve `core.js` as the pure domain/derivation layer, introduce a shared IndexedDB adapter in `js/storage.js` for attachments, Habit logs, Goal history, and recovery snapshots, and keep `app.js` as the browser orchestration/rendering layer. Migrate state non-destructively from schema v2 to schema v3, and keep Search behavior unchanged.

**Tech Stack:** HTML5, CSS3, vanilla JavaScript, Node `node:test`, Python Playwright sync API, IndexedDB, localStorage, JSZip.

**Spec:** `docs/superpowers/specs/2026-09-15-todo-v1-3-design.md`

## Global Constraints

- Base implementation is the complete V1.2 archive: `/mnt/data/todo-html-prototype-v1.2.zip`.
- Final app remains a static browser prototype with no framework and no build step.
- Schema version becomes `3`.
- Existing Search behavior remains unchanged.
- No bulk actions.
- Today remains the primary daily workflow.
- No widget/dashboard system.
- No full hourly time-blocking calendar.
- Existing V1.2 Task/Project/Tag/attachment IDs must survive migration unchanged.
- Existing V1.2 attachments must remain readable after migration.
- All entity deletes require confirmation and then provide Undo.
- Reset and Restore/Replace All require safety ZIP + internal recovery snapshot + typed confirmation.
- Habit logs and Goal history live in IndexedDB, not the main localStorage JSON.
- Visual redesign/polish is out of scope; new UI must reuse the existing V1.2 design system and component language.
- The current `/mnt/data` artifact workspace is not a Git repository. Commit commands below are required when executing in a Git-backed copy; when executing directly in `/mnt/data`, record the same task boundaries in the implementation log instead of silently inventing commits.

- [ ] **Step 3: Implement migration/validation with explicit V2 preservation**

Add the V3 normalizer in `core.js`. The implementation must first reuse the V2 normalizer, then add V3 fields without rewriting existing IDs or V1.2 values:

```js
function migrateStateV3(input) {
  if (!input || typeof input !== 'object') return { ok: false, reason: 'invalid-state' };
  if (![1, 2, 3].includes(input.version)) return { ok: false, reason: 'unsupported-version' };

  const base = input.version === 3
    ? { ok: true, state: JSON.parse(JSON.stringify(input)), migrated: false }
    : migrateStateV2(input);
  if (!base.ok) return base;

  const state = base.state;
  state.version = 3;
  state.areas = Array.isArray(state.areas) ? state.areas : [];
  state.goals = Array.isArray(state.goals) ? state.goals : [];
  state.habits = Array.isArray(state.habits) ? state.habits : [];
  state.templates = Array.isArray(state.templates) ? state.templates : [];
  state.savedViews = Array.isArray(state.savedViews) ? state.savedViews : [];

  state.tasks = state.tasks.map(task => ({
    ...task,
    areaId: task.areaId || null,
    goalIds: Array.isArray(task.goalIds) ? task.goalIds : [],
    plannedTime: normalizeTime(task.plannedTime),
    dueTime: normalizeTime(task.dueTime),
  }));

  state.projects = state.projects.map(project => ({
    ...project,
    areaId: project.areaId || null,
    goalIds: Array.isArray(project.goalIds) ? project.goalIds : [],
    isArchived: Boolean(project.isArchived),
  }));

  return validateStateV3(state);
}
```

`validateStateV3` must return `{ ok: true, state, migrated }` for valid states and a specific `{ ok:false, reason }` for broken relation/shape cases.
