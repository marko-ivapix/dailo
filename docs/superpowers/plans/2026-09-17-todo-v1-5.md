# Dailo V1.5 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the approved V1.5 daily-execution, progress, planning, knowledge, personalization and recovery improvements without breaking V1.4.

**Architecture:** Keep the local-first vanilla JavaScript architecture. Add optional normalized fields to the existing metadata model, derive time blocks and insights from existing entities, and keep each UI domain in its existing `js/*-ui.js` module. Keep orchestration and persistence coordination in `js/app.js`.

**Tech Stack:** HTML, CSS, vanilla JavaScript, localStorage, IndexedDB, Node built-in test runner, isolated Playwright browser scripts.

**Spec:** `docs/superpowers/specs/2026-09-17-todo-v1-5-design.md`

## Global Constraints

- Preserve Today-first workflow and existing V1.4 behavior.
- Do not change global Search behavior or add bulk actions.
- Keep the existing dark technical design system and no-gradient language.
- Keep local-first storage; no backend, accounts, cloud sync, AI or team collaboration.
- New fields must be optional and normalized safely for old V1.2/V1.3/V1.4 state.
- Write a failing test before production code for each new behavior.
- All normal destructive actions remain confirmation → delete → Undo.
- Browser checks use the isolated headless runtime; never open the user's personal Chrome.

## File map

- `js/core.js`: shared normalization, date rules, focus selection and derived calculations.
- `js/storage.js`: normalized state defaults and IndexedDB snapshot helpers.
- `js/app.js`: routing, event delegation, Today/Review coordination and persistence.
- `js/tasks-ui.js`: Task Properties, inline actions and Quick Add.
- `js/goals-ui.js`: Goal metrics, health and linked progress display.
- `js/habits-ui.js`: minimum/ideal/grace insights and recovery display.
- `js/calendar-ui.js`: timed Task blocks and conflict rendering.
- `js/knowledge.js`: Notes/Resources metadata and filters.
- `js/templates-ui.js`, `js/saved-views-ui.js`: template variables and dashboard preferences.
- `js/backup.js`: V1.5 backup/snapshot validation and selective restore.
- `css/styles.css`, `index.html`: V1.5 surfaces and responsive polish.
- `tests/core-v1-5.test.js`, `tests/storage-v1-5.test.js`: deterministic behavior tests.
- `tests/ui-v1-5.py`: isolated browser smoke and interaction coverage.

### Task 1: V1.5 data foundation and derived helpers

**Files:**
- Modify: `js/core.js`, `js/storage.js`, `js/backup.js`
- Create: `tests/core-v1-5.test.js`, `tests/storage-v1-5.test.js`

**Interfaces:**
- `normalizeState(state)` adds safe defaults for `task.durationMinutes`, `settings.focusTaskIds`, `goal.currentValue`, `goal.targetValue`, `goal.unit`, `habit.minimumTarget`, `habit.idealTarget`, `habit.graceDays`, resource metadata and dashboard preferences.
- `selectFocusTasks(tasks, focusTaskIds, limit = 3)` returns at most three open task IDs that still exist.
- `getGoalHealth(goal, now)` returns `on-track`, `at-risk`, `overdue` or `complete`.
- `getHabitTargetStatus(habit, periodStats)` returns minimum/ideal completion state.
- `getTimedTaskBlocks(tasks, date)` returns derived timed blocks with `taskId`, `startMinutes`, `durationMinutes` and `endMinutes`.

- [ ] **Step 1: Write failing tests** for normalization of old state, focus selection limit, Goal health boundaries, Habit target status and timed block ordering/conflicts.
- [ ] **Step 2: Run focused tests and verify they fail** with missing helpers/defaults.
- [ ] **Step 3: Implement minimal normalization and pure helpers** without changing existing semantics.
- [ ] **Step 4: Run `node --test tests/core-v1-5.test.js tests/storage-v1-5.test.js`** and then the existing suite.
- [ ] **Step 5: Commit** as `feat: add v1.5 data foundation`.
