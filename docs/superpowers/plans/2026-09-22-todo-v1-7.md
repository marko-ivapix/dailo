# Dailo V1.7 Implementation Plan

> **For agentic workers:** Use `superpowers:subagent-driven-development`. Every implementation task gets a fresh implementer subagent, then a separate fresh reviewer subagent. Review findings must be fixed before the next task.

**Goal:** Deliver the approved V1.7 stabilization release: complete mobile access, harden accessibility and overlays, broaden regression evidence, strengthen data/backup safety, and apply only targeted polish before the later full redesign.

**Architecture:** Keep canonical local-first records and V3 storage. Add small pure validation/projection helpers to existing core/storage modules, keep route rendering in focused UI modules, and keep all new navigation and preference state derived or additive. Recovery-sensitive operations remain behind the existing safety ZIP, typed confirmation, and rollback boundaries.

**Tech Stack:** HTML, CSS, vanilla JavaScript, localStorage, IndexedDB, Node built-in test runner, existing Python static/UI checks, and the existing ZIP backup library.

**Spec:** `docs/superpowers/specs/2026-09-22-todo-v1-7-design.md`

**Baseline:** V1.6 commit `9655b4c`, automated suite 207/207, clean worktree.

## Global execution rules

- Verify the existing isolated worktree before implementation; do not create a second worktree.
- Preserve V1.6 semantics, Search behavior, no-bulk rule, local-first storage, and branding.
- Use test-first development: failing focused test, minimal implementation, focused tests, regression tests.
- Do not open isolated Chromium or the user's personal Chrome. Browser acceptance is recorded separately and never inferred from static inspection.
- Maintain `docs/superpowers/progress-v1-7.md` after every task with implementation, review, tests, and unresolved manual gates.
- Each task sequence is: fresh implementer → focused tests → fresh reviewer → fix critical/important findings → commit → ledger update.

## File map

- `index.html`: application shell, navigation anchors, and live-region markup.
- `js/app.js` and focused `*-ui.js` modules: route rendering, dialogs, popovers, and interaction wiring.
- `js/core.js`: pure projections, date math, validation, migration, and Goal/Habit calculations.
- `js/storage.js` and `js/backup.js`: IndexedDB records, snapshots, ZIP validation, export/import, and rollback.
- `css/styles.css`: existing compact-density and responsive tokens; no new framework.
- `tests/`: Node, Python static/UI, and browser-regression harnesses.
- `docs/`: release spec, plan, ledger, architecture, feature, and user-facing documentation.

## Review focus

- A phone-width user must reach an existing record after creating it without relying on Quick Add.
- A keyboard or screen-reader user must never lose focus context in a nested dialog/popover.
- A DST transition must not change a recurring reminder's local wall-clock time.
- A malformed or oversized backup must fail before destructive replacement and preserve the original workspace.
- Two tabs must not silently overwrite a newer canonical write or leave derived views falsely stale.
