# Dailo V2.0-a implementation plan — Sync in the web app

**Spec:** `docs/superpowers/specs/2026-10-08-todo-v2-0-design.md` (approved 2026-10-08)
**Ledger:** `docs/superpowers/progress-v2-0a.md`
**Baseline:** V1.12 on `main` (`31fb23d`).
**Version:** `APP_VERSION` `2.0.0-alpha.1`.

## Step 1 — Server schema and setup guide

- [ ] `supabase/migrations/0001_sync.sql`:
  - `records` with Row Level Security;
  - the `updated_at` trigger (server clock);
  - `record_history` with its trigger;
  - `delete_my_account()`.
- [ ] `docs/v2/SUPABASE_SETUP.md`, step by step for the user:
  - EU project; run the SQL;
  - e-mail template with `{{ .Token }}`; site URL;
  - where the URL and anon key go; the service-role key never;
  - e-mail rate limits on the free tier.
- [ ] Static tests for the SQL: RLS enabled, `auth.uid()` policies, triggers, `security definer` with a fixed `search_path`, and an execute grant only to `authenticated`.

## Step 2 — Sync core (`js/sync.js`, no dependencies)

- [ ] Failing tests first (`tests/sync-v2-0a.test.js`), using an in-memory fake Supabase (`tests/support/fake-supabase.js`) with OTP auth, the records REST API, RLS by token and a server clock.
- [ ] **Pure parts:**
  - `collectRecords` (strips `attachmentIds` and the device-local settings);
  - `hashRecord`, `diffRecords`, `applyRemote` (keeps local `attachmentIds` and device settings; tombstones; habit-log same-date replacement).
- [ ] **`createClient({ url, anonKey, fetch, now })`:**
  - auth: `requestCode`, `verifyCode`, `refresh`, `signOut`, `deleteAccount`;
  - data: `push`, `pull` (paged, 5-second overlap).
- [ ] **`syncOnce`:**
  - push, then pull; shadow and cursor update;
  - the first-sign-in modes `merge`, `server` and `device`;
  - errors reported, never thrown into the UI loop.
- [ ] **Two-device scenarios:**
  - create, edit, delete and habit-log conflicts;
  - attachments stay local;
  - settings keep device keys;
  - a stale session refreshes;
  - delete account.

## Step 3 — App and Settings

- [ ] `js/sync-config.js` (`url`, `anonKey`, empty by default). It and `js/sync.js` load before `js/app.js` and are precached.
- [ ] **Settings "Sinhronizacija" card**, shown only when configured:
  - e-mail, then code;
  - when signed in: account, last sync, error, "Sinhronizuj sada", "Odjavi se", "Obriši nalog" (typed confirmation `OBRIŠI`).
- [ ] **First sign-in choice:** when both sides have data, a dialog offers merge, server or device. The server and device modes take a recovery snapshot first.
- [ ] **Triggers:** start, `visibilitychange`, `online`, 3 seconds after a save, and every 5 minutes. A sync never applies pulls while a dialog is open or a global operation runs.
- [ ] **Apply:** normalized state goes through `saveState`, habit logs through `TodoStorage`, then the metrics refresh and a render.
- [ ] Catalog entries; untranslated-text and class audits.

## Step 4 — Release

- [ ] `APP_VERSION` and `sw.js` `VERSION` `2.0.0-alpha.1`; release tests accept a pre-release suffix.
- [ ] Beta guide: a short note that sync is coming and optional (only once the user enables it).
- [ ] Docs sync, ledger, verification, push. PR into `main` when the user asks.
