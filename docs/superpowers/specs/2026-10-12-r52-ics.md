# R52 — the calendar as an .ics file

**Date:** 2026-10-12 · **Status:** the user's request (improvement 5, "moze sve"). · **Release:** `2.0.0-alpha.79`.

Settings → Podaci gains the row "Kalendar (.ics)" with **Izvezi** and **Uvezi**. Nothing in the data model changes: an import creates ordinary tasks.

## Export (`Core.calendarIcs(tasks, { now, dueLabel })`)

- **Which tasks:** every open task in `listTasks()` (so archived projects stay out) with a planned or due date. Completed and undated tasks are left out.
- **A plan:**
  - with a time, it becomes an event in UTC lasting `durationMinutes`, or 30 minutes without a duration;
  - without a time, it becomes an all-day event.
  - Its UID is `<task id>-plan@dailo`.
- **A deadline on another day:** it becomes a second event "Rok: <title>", 30 minutes or all day, with the UID `<task id>-due@dailo`. A deadline on the planned day adds nothing.
- **Notes:** they become the `DESCRIPTION`.
- **Format (RFC 5545):** text is escaped (`\`, `;`, `,`, new lines), lines are folded at 75 octets, and every line ends in CRLF. `PRODID` is `-//Dailo//Dailo//SR`.
- **Saving:** `DailoPlatform.files.saveFile` saves it as `dailo-kalendar-<date>.ics`. That is a download on the web and the share sheet in the app. With nothing to export, a message says so.

## Import (`Core.parseIcsEvents(text)`, `Core.icsImportTasks(events, tasks, today)`)

- **Reading:**
  - Folded lines are unfolded, and the first value of each property counts.
  - `STATUS:CANCELLED` events are left out.
- **When an event happens:**
  - **All-day:** `VALUE=DATE`, or a date without a time.
  - **UTC:** a `Z` time is read in UTC.
  - **Time zones:** a `TZID` time is converted from that zone with `Intl`, and an unknown zone, such as a Windows zone name, reads as local.
  - **Floating:** a time without a zone reads as local.
- **Duration:** from `DTEND` or `DURATION` (weeks, days, hours, minutes, seconds).
- **What becomes a task:**
  - only events from today on;
  - not repeating ones (`RRULE`/`RDATE`), since Dailo's own repeat rule is set by hand;
  - not ones with the same title (case aside), day and time as an open task or as an earlier event in the file;
  - at most 500 per file.

  Each draft keeps the title, the description as notes, the date and time, and a duration of 1–1440 minutes. An event without a title becomes "Događaj bez naslova".
- **Asking first:** the confirm dialog asks "Uvesti događaje iz kalendara?" and lists the number of new tasks and what is skipped (past, repeating, already here). Its button is blue, through the new `confirmKind: 'primary'`; `messageParams` lets a dialog message carry numbers.
- **After the import:** the tasks are planned, outside Inbox and without a project. Poništi removes them again (`snapshotTasks`/`restoreTasks`). Events over the limit are named in a message.
- **Errors:** a file that cannot be read says so.
