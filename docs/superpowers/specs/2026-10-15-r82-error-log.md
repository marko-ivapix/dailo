# R82 — The last errors go along with a problem report

**Date:** 2026-10-15 · **Status:** point 5 of the outside review ("Uz prijavu problema automatski pošaljite verziju, uređaj i dnevnik grešaka, bez podataka korisnika"), accepted by the user ("Sve se slažem…"). The source sent the version and the device, but collected no errors. · **Release:** `2.0.0-alpha.109`. No data-model change; one new device-local key.

## The change

- **Collecting (`js/app.js`):** `captureErrors()` runs first in `init`. It records:
  - uncaught errors (`error`, with the file and line);
  - unhandled rejections;
  - `console.error`, which the app uses for errors it catches. The original output stays.
- **What is kept (`recordError`):** the device-local key `dailoErrorLog` keeps the newest 10 errors, newest first. It is outside state, backups and sync, and listed in CLAUDE.md. Each entry is `{ at, version, where, message, count }`:
  - `where` is the file name and line, without the address;
  - `message` is cleaned by `Release.cleanErrorText`: quoted text becomes `"…"`, an e-mail address becomes `[e-mail]`, spaces are collapsed and it is cut at 160 characters, so no task title, note or address goes along;
  - the same cleaned message from the same place counts up instead of adding a line;
  - an empty message is not kept, and blocked storage stays quiet.
- **The report (`Release.problemReportMailto`):** after the device details, "Poslednje greške (bez ličnih podataka):" lists at most 5 errors as `time (UTC) · version · place · message (×count)`, or "nema". `environmentInfo()` passes the log. The user sees the e-mail before sending it.
- **Texts:**
  - **Pomoć:** "Otvara e-poruku sa verzijom aplikacije, podacima o uređaju i poslednjim greškama. Tvoji podaci se ne prilažu."
  - **The FAQ and the guide** say the same.
  - **"Šta je novo"** gets a line, and its version range now ends at alpha.109.
- **Not changed:** the privacy policy does not describe problem reports. A sentence about them can be added with the user's approval.
