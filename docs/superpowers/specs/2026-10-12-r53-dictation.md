# R53 — voice input in Quick Add

**Date:** 2026-10-12 · **Status:** the user's request (improvement 6, "moze sve"). · **Release:** `2.0.0-alpha.80`.

## Where it works

- **In the browser (web and installed PWA):** a microphone sits next to the Quick Add title, but only where the browser recognizes speech (`SpeechRecognition` or `webkitSpeechRecognition`), such as Chrome, Edge and Safari. Elsewhere the field stays as before.
- **In the phone apps:** the Capacitor WebViews have no speech recognition, so dictation stays on the keyboard's microphone key, which already writes into the field.
- **No native plugin:** `@capacitor-community/speech-recognition` 7.0.1 was tried and removed. It has no Swift package, and `cap sync` warned that it is not compatible with the iOS project's Swift Package Manager setup. Adding it would risk the first iOS build and would need microphone permissions in both stores for little gain over the keyboard.

## Behavior

- **Starting:** a tap listens once in Serbian (`sr-RS`, `interimResults`, not continuous). The button turns red and pulsing, and gets `aria-pressed="true"` and the label "Zaustavi diktiranje".
- **The words:** they join the typed title live. Serbian recognition may answer in Cyrillic, so `Core.cyrillicToLatin` writes it in Latin like the rest of the app, digraphs included (Љ → Lj, Џ → Dž). An `input` event updates the preview of dates, tags and places.
- **Stopping:** a second tap stops, and so does the end of speech; the field gets the focus back. Closing Quick Add aborts listening (`stopDictation` in `closeModal`).
- **Errors:** a refused microphone, silence, no microphone and a network failure each give a short Serbian message. An aborted session says nothing.
- **Privacy:** the browser's own service recognizes the speech; Chrome and Edge send the audio to Google or Microsoft, and Safari to Apple. Dailo keeps no audio, only the recognized text in the field. The privacy page says so in a new section.
