# Dailo V1.10 — Smart Quick Add

**Status:** approved scope (user request 2026-10-08: "Odradi sve tačke", roadmap Phase 4 item "Smart Quick Add").
**Baseline:** V1.9.1 on `main`.
**Roadmap:** `docs/superpowers/plans/2026-10-07-release-roadmap.md`, Phase 4.

## Goal

Capture a fully described task in one line, in Serbian or English, and see what Dailo understood before saving:

```text
Pošalji ponudu +Klijenti #posao !visok rok petak 45min sutra u 9:30
```

Result:
- title "Pošalji ponudu";
- project "Klijenti", tag "posao", priority high;
- due Friday, 45 minutes, planned tomorrow at 09:30.

## Existing behavior (kept)

- `#tag` (existing tags only), `!high` / `!medium` / `!low` anywhere in the title.
- A trailing plan day (`today`, `tomorrow`, weekdays; Serbian `danas`, `sutra`, weekdays with or without diacritics, optionally after `u`).
- A trailing time (`HH:MM`, `at HH:MM`, `u H:MM`).
- A phrase that does not parse stays in the title untouched.
- An invalid time or date leaves the whole title unparsed.
- An explicitly chosen Plan date wins over parsed text, and parsing it is skipped.
- `Core.parseQuickPlanPhrase` and `Core.splitQuickTime` keep their V1.9 results.

## Design

### A. One pure parser

`Core.parseQuickAdd(text, { today, tags, projects, areas, parsePlan = true })` returns `{ title, plannedDate, plannedTime, dueDate, durationMinutes, priority, tagIds, projectId, areaId }`. Each field is `null` (or `[]`) when absent. It is pure and Node-testable. `parseQuickAddTitle` in `js/app.js` delegates to it.

### B. Trailing clauses

The parser reads clauses from the end of the title, right to left, in any order. It stops at the first word that is not part of a clause. Each kind of clause fills one slot; a second clause of the same kind stops parsing and stays in the title.

| Slot | Serbian | English | Notes |
| --- | --- | --- | --- |
| Plan date | `danas`, `sutra`, `prekosutra`, weekdays (`u sredu`), `za N dana`, `za N nedelja/nedelje`, `15.10.`, `15.10.2026.` | `today`, `tomorrow`, weekdays, `in N days`, `in N weeks`, `2026-10-15` | Today's weekday means next week. A date without a year means its next occurrence. |
| Time | `u 9:30`, `9:30` | `at 09:30`, `09:30` | Single-digit hour padded. A time right after `do` is not parsed ("Uradi do 17:00" stays as written). |
| Due date | `rok <day>`, `do <day in genitive>` (`do petka`, `do srede`, `do sutra`, `do 15.10.`) | `due <day>` | `<day>` is any plan-date word or date above. |
| Duration | `45min`, `45 min`, `45m`, `1h`, `1,5h`, `1h30`, `1h30m`, `2 sata` | `45min`, `1h`, `1.5h`, `1h30m` | 1–1440 minutes; `m` only when attached to the number. |

A weekday right after `za` is not parsed: `za nedelju` means "for Sunday" (V1.9 parsed the weekday and left `za` in the title).

Genitive weekday forms after `do`: `ponedeljka`, `utorka`, `srede`, `četvrtka`/`cetvrtka`, `petka`, `subote`, `nedelje`.

A clause that matches syntactically but is invalid (for example `25:00`, `31.02.`, `0min`, `za 0 dana`) leaves the whole trailing part unparsed, as in V1.5. The tokens in C still apply.

### C. Tokens anywhere

| Token | Meaning |
| --- | --- |
| `#name` | Existing tag (unchanged). |
| `!high` `!medium` `!low` / `!visok` `!srednji` `!nizak` | Priority. |
| `+name` | Existing project. |
| `@name` | Existing Area. |

- Names match case-insensitively, ignoring spaces, `_` and `-`. Diacritics are optional (`č`/`ć` → `c`, `š` → `s`, `ž` → `z`, `đ` → `dj`), so `+kucni_projekat`, `+Kućni-projekat` and `+KućniProjekat` all match the project "Kućni projekat". `#tag` matching is unchanged.
- An unknown `+name` or `@name` stays in the title, like an unknown `#tag`.
- A project wins over an Area, as in the task model, where `areaId` is null when `projectId` is set.

### D. Precedence when saving

Values from the Quick Add pickers win over parsed values:
- plan date: as before;
- due date, duration, project and Area: when set;
- time: when explicitly set.

Parsed priority wins over the default `none`, as before. Inbox placement uses the resolved project and plan date.

### E. Live preview

- **Preview line:** under the title, a `data-quick-preview` line (`aria-live="polite"`) shows what was understood: plan date and time, due date, duration, project, Area, tags and priority. Each item has an icon and Serbian text, and the line updates on every keystroke.
- **When it is empty:** nothing is recognized, so the line is not shown.
- **Plan chip:** it keeps updating as in V1.9; the untranslated fallback was fixed in V1.9.1.
- **Picker chips:** they keep showing only explicit picker values. The preview line is the single place for parsed values.

### F. Out of scope

- Voice input. iOS keyboard dictation already types into the title field.
- Creating new projects, Areas or tags from tokens.
- Reminders and recurrence syntax.
- An escape character for keywords.
- Natural phrases such as "sledeće nedelje" or "za nedelju". The latter is ambiguous: it can mean "in a week" or "for Sunday".

## Tests (written first)

- `tests/quick-add-v1-10.test.js`:
  - every row of tables B and C, in Serbian and English;
  - clause order independence;
  - stop-at-first-non-clause;
  - one clause per slot;
  - invalid clause → whole title unchanged;
  - `do 17:00` not parsed;
  - project-over-Area;
  - name matching;
  - unknown sigils kept;
  - `parsePlan: false` keeps plan words in the title;
  - existing V1.5/V1.9 Quick Add assertions unchanged.
- App integration (VM slice of `parseQuickAddTitle` + `createTask`):
  - parsed fields land on the task;
  - picker values win;
  - Inbox uses the resolved project.
- Preview: a rendered preview with a parsed project, due date and duration, translated through the catalog; nothing is rendered when nothing is recognized.
- The i18n catalog completeness and untranslated-text audits stay green.
