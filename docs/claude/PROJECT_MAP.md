# Current implementation project map

This map describes the `2.0.0-alpha.3` source on `main` (modernization M1–M11, merged through PR #8) inspected on 2026-10-09; the rows below were written for V2.0-a and the section "Modernization and the native app" lists what changed since. It is an onboarding aid for Claude, not a replacement for `AGENTS.md`, the versioned specifications, or acceptance evidence. The directory name still says V1.3; README describes V2.0-a, V1.12, V1.11, V1.10 and V1.9 functionality. Inspect source before making version or completion claims.

## Read paths for changes

- Task membership or ordering: start in `core.js`, then inspect `app.js` daily-view/render/action helpers and `tasks-ui.js`.
- Goal/Habit UI: start in the corresponding adapter; inspect app context and `core.js` rules before modifying links or history.
- Persistence, deletion, migration or recovery: inspect `storage.js`, `backup.js` and the coordinating lifecycle in `app.js` together.
- Notes/Resources: inspect `knowledge.js`, shared ownership in `storage.js`, backup validation and app attachment operations.
- Cleaning: inspect `cleaning-ui.js` and shared Project/Task behavior; there is no separate room/chore collection.
- Styling: inspect `styles.css` and the markup generated by the responsible adapter/controller, including mobile and overlay states.
- User-visible text: inspect the `tr`/`trn`/`msg` call in the responsible module and its entry in `js/i18n-sr.js`; `tests/i18n-v1-9.test.js` checks both.
- Install/offline: inspect `manifest.webmanifest`, `sw.js`, the `index.html` head and `registerServiceWorker` in `app.js`; `tests/offline-v1-9.test.js` keeps the precache list equal to the referenced files.
- Quick Add parsing: start in `parseQuickAdd` in `core.js`, then `parseQuickAddTitle`, `createTask`, `quickParsePreview` and the `quick-title` input handler in `app.js`; tests are `tests/quick-add-v1-5.test.js`, `quick-add-v1-9.test.js` and `quick-add-v1-10.test.js`.
- Weekly review: `deriveWeeklyReview` and the log functions in `core.js`, `js/review-ui.js`, then `weeklyReviewNotice`, `completeWeeklyReview` and the route/navigation entries in `app.js`; `settings.weeklyReviews` validation in `backup.js`; test `tests/weekly-review-v1-11.test.js`.
- Time-blocking and capacity: `daySchedule`, `dayLoad`, `dailyCapacityMinutes` in `core.js`, `renderDayView` in `calendar-ui.js`, `navigateCalendar`, `todayCapacityItem`, `durationLabel` and the drag/drop and `data-task-time` handlers in `app.js`, the capacity row in `settings-ui.js`; test `tests/time-blocking-v1-12.test.js`.
- Sync: `js/sync.js` (pure parts, client, `syncOnce`), the sync block and wiring in `app.js`, the card in `settings-ui.js`, `js/sync-config.js`, the server schema `supabase/migrations/0001_sync.sql` and the user guide `docs/v2/podesavanje-supabase.md`; tests `tests/sync-v2-0a.test.js` (core against `tests/support/fake-supabase.js`, SQL static checks) and `tests/sync-app-v2-0a.test.js` (loading, config, Settings card, the app block in a vm).
- Release metadata: `js/release.js`, `sw.js` `VERSION` and the newest release test change together. Only the newest release test pins the exact version (`tests/audit-fixes-m12.test.js`: `2.0.0-alpha.4`, also `package.json`); `tests/decisions-m11.test.js` requires ≥ alpha.3; `tests/release-m10.test.js` requires ≥ alpha.2 with `sw.js`, `package.json` and its lock equal; `tests/sync-app-v2-0a.test.js` requires a 2.x version that `sw.js` follows; `tests/time-blocking-v1-12.test.js`, `tests/quick-add-v1-10.test.js` and `tests/weekly-review-v1-11.test.js` require ≥ 1.12 / ≥ 1.10.0 / ≥ 1.11.0, and `tests/release-v1-9.test.js` (which accepts a pre-release suffix) and `tests/beta-v1-9-1.test.js` "≥ V1.9" / "≥ 1.9.1". `sw.js` must follow `APP_VERSION` (checked by `tests/offline-v1-9.test.js` and the V1.9.1–V2.0-a release tests).
- Beta material: `uputstvo.html` (tester guide, checked by `tests/beta-v1-9-1.test.js`) and `docs/beta/provera-pre-bete.md` (beta checklist B1–B36; B25–B30 cover V1.10–V1.12, B31–B36 the sync), both Serbian.

## Tests and documentation

The V2.0-a tree has 48 Node test files (including `tests/design-v1-8.test.js`, the V1.8 visual contracts, seven V1.9 files, `tests/beta-v1-9-1.test.js`, `tests/quick-add-v1-10.test.js`, `tests/weekly-review-v1-11.test.js`, `tests/time-blocking-v1-12.test.js`, `tests/sync-v2-0a.test.js` and `tests/sync-app-v2-0a.test.js`), 23 runtime JavaScript modules in `js/` plus `sw.js`, and 19 Python test/helper files in `tests/`. ## External assets

Since V1.9 every runtime asset is local: Geist and Space Grotesk in `vendor/fonts/`, Phosphor 2.1.1 in `vendor/phosphor/`, JSZip in `vendor/`. `index.html` has no `http(s)://` reference (asserted by `tests/offline-v1-9.test.js`). V1.4–V1.8 loaded the fonts from Google Fonts and Phosphor from unpkg. The only external server is the optional Supabase project of V2.0-a: `js/sync.js` calls it with `fetch` only when `js/sync-config.js` is filled and the user signs in; the service worker leaves those cross-origin requests to the network. The `mailto:` problem report only opens the user's mail app (an address is configured since V1.9.1).
